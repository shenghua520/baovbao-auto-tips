## ⚡ API 速查

### 通用

```
POST https://mall.baovbao.com/admin/<模块>/<动作>
Content-Type: application/json;charset=UTF-8
Header: uid / sid / token
```

### 最常用 5 个

| 接口 | 用途 | 关键参数 |
|---|---|---|
| `/admin/Login/captcha` | 取验证码（base64 图） | `{}` |
| `/admin/Login/adminLogin` | 登录 | `account` / `password` / `captcha` |
| `/admin/goodsCate/lists` | 分类/品牌列表 | `cate_type`(1分类/3品牌) |
| `/admin/good/lists` | 商品列表 | **`good_source`（1自营/3供应链）** |
| `/admin/good/edit?good_id=` | 改商品 | 全量回填 30+ 字段 |

### 三个致命陷阱

| 陷阱 | 报错 | 解决 |
|---|---|---|
| 分类/品牌漏 `period` | `1002 上架的商城 必须为正整数~` | 加 `period: 72` |
| `good/edit` 用 form-data | `品牌参数错误` | 改用 JSON body |
| `good_source` 传 `"all"` | 拉不到数据 | 循环查 `1` 和 `3` |

### 探测统计（实测 2026-09-23）

| 状态 | 数量 |
|---|---|
| ✅ `code=0` 有效（空参数即可） | 141 |
| ⚙️ `code=1002` 需参数 | 60 |
| ✏️ 写操作（未探测，避免副作用） | 237 |

## 批量操作经验（11 节）

### 0. 心法：review 流程

**任何生产数据变更，必须串行四步**：

1. **拉真实数据**（不凭印象/历史快照）
2. **本地 dry-run**（算清单 + 打印 review）
3. **1 条试改**（回读校验 + 验证资源可达）
4. **批量执行**（每 50-100 条打点，失败即停）

> 跳过 = 必然踩坑。本次栽过两次：抄早期脚本剥域名、用后台脏名匹配。

### 1. 鉴权

后台 Vue SPA，所有 API 走 Header：`uid` / `sid` / `token` + `Content-Type: application/json`。

### 2. 关键 API 契约

| 接口 | 必带 | 踩坑 |
|---|---|---|
| `goodsCate/edit` | **`period:72`** | 漏了报 1002 |
| `goodsCate/lists` | `cate_type` | 1=分类，3=品牌 |
| **`good/edit`** | **JSON body** | form-data 报"品牌参数错误" |

改商品必须 **先 `detail` 拿全字段 → 改 → 30+ 字段全回填**。

### 3. 名称限制：≤ 6 字符

`goodsCate/add` 拒超 6 字符名。新建前做 length check。

### 4. 排序设计

| 维度 | 依据 |
|---|---|
| 大类 sort | 业务方指定顺序（1-9） |
| 二级 sort | **购买链路**（非字典序）：铅笔→卷笔刀→橡皮擦→修正带→笔芯… |
| 品牌 sort | 京东/天猫销量档位：头部 `10` / 强腰 `30` / 腰 `60` / 长尾 `200` / 无品牌 `999` |

### 5. 商品关联策略（避免误匹配）

- **用规范品牌库匹配**，不用后台历史脏名（`TANGO`抢`天章`）
- 排除易撞词：`729`(商品编码) / `人教`(人教版) / `蝴蝶`(蝴蝶结) / `童趣`(儿童趣味) / `樱花`
- **只改"无品牌/无二级"商品**，已有正确值不动
- 品牌名**长度降序**匹配（`李宁儿童` 先于 `李宁`）

### 6. 图片 URL 必须带完整域名

见 [08 · 图片与文件规范](./docs/08-图片与文件规范.md)。

> 抄参考项目时只读**最新版/修复版**，不要按"main 分支"挑早期脚本。

### 7. 旧分类下架顺序

```
1. 建新分类  →  2. 迁移商品  →  3. 验证旧分类无商品  →  4. 删除旧分类
```

> `good/lists` 默认只查 source=1，**供应链商品（source=3）会漏**，导致以为清空其实没清 → 删除报 10501。

### 8. 销量按用户画像分档

高频消耗品（铅笔/抽纸/牛奶）3000-9000，中频（书包/鞋）600-3000，低频高客单（扫地机）80-500。
用**偏态随机**（15%爆款/40%中位/45%靠下限）+ 取整到 10。

### 9. 性能与并发

- 每请求 200-500ms，**串行别并发**（后台并发触发 502）
- 1534 个商品迁移约 8-12 分钟（`time.sleep(0.08~0.15)`）

### 10. 调试工具

- **playwright + chromium-1243** 可断点查后台
- **agent-browser 别用**：eval 上下文和截图上下文是分开的
- **`/admin/index/logs`** 可反查自己调过的接口和参数
- 参考项目：mimo desktop（`~/XiaomiMiMoProjects/2026-09-21/https-mall-baovbao-com-admin-index-2`）

### 11. 一句话总结

> **拉真实数据 → dry-run 出 review → 1 条试改 → 批量执行 → 验证**
> **涉及 URL/ID 的字段，先读参考项目最新版（不是直觉最早版）**
> **抄脚本前先看它的"事故复盘"和"修复版"**
