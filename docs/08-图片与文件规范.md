# 08 · 图片与文件规范（🔴 必读）

> 这是本次改造中**最惨痛的教训**：脚本把图片 URL 的域名剥掉 → 全站 1534 个商品图片失效。
> 本章说明正确的图片 URL 处理和修复方法。

---

## 一、事故复盘

### 现象

商品迁移到新分类后，**所有商品图片不显示**（小程序 + 后台都看不到）。

### 根因

后台 `good/detail` 返回的图片字段是**完整 URL**：

```
https://mall.baovbao.com/upload/0/supply/9/2413039_606223684.jpeg
https://img13.360buyimg.com/n12/jfs/t1/434004/...
https://img.picing.com/8178530514018994914_800X800_37W.jpg?imageMogr2/...
```

但参考项目的**早期脚本**里有个 `strip_url()` 函数，把域名剥掉只留路径：

```python
def strip_url(u):
    # ❌ 危险！会把 https://mall.baovbao.com/upload/x.jpg 变成 /upload/x.jpg
    if s.startswith("http://") or s.startswith("https://"):
        rest = s.split("//", 1)[-1]
        slash = rest.find("/")
        return rest[slash:] if slash >= 0 else ""
    return s
```

**回写后图片全失效。**

### 教训

> 🔴 **抄参考项目时，只读最新版/修复版，不要按"main 分支"直觉挑早期脚本。**
> 该项目的**后来版本**已经写了 `restore_image_urls.py` 修复这个问题——我没读完就开始改。

## 二、正确的域名映射规则

图片 URL 按**路径特征**决定域名：

| 路径特征 | 域名 | 来源 |
|---|---|---|
| `/upload/...`、`/images/...`、`/YYYY/MM/...` | `https://mall.baovbao.com` | 商城自有 |
| `/i/...` | `https://d5ma.img.apiunion.com` | apiunion |
| `/n12/...`、`/sku/jfs/...`、含 `/jfs/` | `https://img13.360buyimg.com` | 京东图床 |
| 含 `imageMogr2` 或 `数字_宽X高_` | `https://img.picing.com` | picing |
| 其他 | `https://mall.baovbao.com` | 兜底 |

### 完整 `restore_url` 实现（直接复用）

```python
import re

APIUNION = "https://d5ma.img.apiunion.com"
JD       = "https://img13.360buyimg.com"
PICING   = "https://img.picing.com"
MALL     = "https://mall.baovbao.com"

def restore_url(u):
    """把相对路径补全为完整 URL（按路径特征判断域名）"""
    if not u:
        return ""
    s = str(u).strip()

    # 1) 已是完整 URL —— 直接返回
    if s.startswith(("http://", "https://")):
        return s

    # 2) 协议相对 //xxx
    if s.startswith("//"):
        path = s[2:]
        if path.startswith("upload/") or re.match(r"^\d{4}/\d{2}/", path) or path.startswith("images/"):
            return MALL + "/" + path
        if path.startswith("i/"):
            return APIUNION + "/" + path
        return "https:" + s

    # 3) 普通路径
    path = s if s.startswith("/") else "/" + s
    while path.startswith("//"):
        path = path[1:]

    # apiunion
    if path.startswith("/i/") or "/i/" in path[:6]:
        return APIUNION + path

    # 京东图床
    if "/jfs/" in path or path.startswith("/n12/") or path.startswith("/sku/jfs"):
        return JD + path

    # picing（imageMogr2 是腾讯云数据万象处理参数）
    if "imageMogr2" in s or re.search(r"/\d{10,}_\d{2,4}X\d{2,4}_", path):
        return PICING + path

    # 商城自有 upload
    if path.startswith("/upload/") or path.startswith("upload/"):
        if not path.startswith("/"):
            path = "/" + path
        return MALL + path

    # 商城自有 images / 日期路径
    if path.startswith("/images/") or re.match(r"^/\d{4}/\d{2}/", path):
        return MALL + path

    # 兜底
    return MALL + path
```

## 三、哪些字段需要修复

商品相关的图片字段，**全部都要 `restore_url`**：

| 层级 | 字段 |
|---|---|
| 商品级 | `cover_img`, `wheel_img[]`, `wheel_img_arr[].url`, `detail_img[]`, `detail_img_arr[].url` |
| SKU 级 | `skus[].cover_img`, `skus[].wheel_img[]`, `skus[].detail_img[]` |

```python
# 商品级
"cover_img": restore_url(detail.get("cover_img")),
"wheel_img": [restore_url(x) for x in (detail.get("wheel_img") or [])],
"detail_img": [restore_url(x) for x in (detail.get("detail_img") or [])],

# SKU 级（容易漏！）
for s in detail.get("skus") or []:
    if s.get("cover_img"):
        s["cover_img"] = restore_url(s["cover_img"])
```

## 四、验证方法（必须做）

改完后**抽查 URL 可达性**（HTTP 200 且 content-type 是 image）：

```python
import requests, random

def verify_image(url):
    try:
        r = requests.head(url, timeout=10, allow_redirects=True)
        ct = r.headers.get("content-type", "")
        return r.status_code == 200 and "image" in ct, r.status_code, ct
    except Exception as e:
        return False, None, str(e)[:50]

# 抽查 10 个商品
random.seed(7)
for gid in random.sample(range(1100, 2700), 10):
    d = post("/admin/good/detail", {"good_id": gid}).get("data") or {}
    if not d:
        continue
    url = d.get("cover_img") or ""
    if not url:
        print(f"{gid}: 无图")
        continue
    ok, st, ct = verify_image(url)
    print(f"{gid}: [{'OK' if ok else 'BAD'}] {st} {ct[:15]} {url[:58]}")
```

**实测结果**：抽查 10 个 → **9 个 OK，1 个 BAD**。

> 那 1 个 BAD 是历史丢失图（URL 返回 JSON 而非图片），属于原数据问题，非本次改造导致。

## 七、一句话总结

> **图片 URL 必须带完整域名。任何"去域名 / 相对路径化"的操作都是破坏性的。**
> 抄参考脚本前先读它的**事故复盘和修复版**。
